# CIFAR10 优化路径与最终训练配方

作者：Shaohan Yang · Team HYS · 2026 年 11 月

## 1 结果概览

我负责的实验从 Wide 基线对照开始，依次探索紧凑残差网络、PreAct SE、SAM 微调、权重平均，再转向双分支 Shake-Shake。最终提交采用 **Shake-Shake-26 2×40d，50,000 张许可训练图片，从零训练 1000 轮**，公榜达到 **0.899（89.9%）**，略高于队内此前的 **0.898**。这两个成绩对应不同模型，最终是否保留两份提交由小组统一决定。

另一条在线蒸馏实验在固定 5,000 张验证集上达到 **97.66%**，但公榜仅 **88.4%**。因此，我将“本地最佳”和“公榜最佳”分别记录，最终主方案选择公榜表现更好的全量训练版。

| 最终候选 | 训练数据 | 轮数与选模 | 独立本地验证 | Public Score |
|---|---|---|---|---|
| Shake-Shake 原始配方 | 45k，保留 5k 验证 | 600 轮，最佳第 600 轮 | 单视图 97.12%；镜像 97.54% | 0.882 |
| B 双教师在线蒸馏 | 45k，保留相同 5k 验证 | 700 轮，最佳第 690 轮 | 单视图 97.58%；镜像 97.66% | 0.884 |
| **A 全量从零重训** | **50k** | **1000 轮，固定取最后一轮** | **无独立验证集** | **0.899** |

公榜成绩来自实际提交回报；A 的 0.899 同时得到最终小组聊天记录确认。私榜成绩尚未知。89.9% 与 89.8% 仅相差 0.1 个百分点，不能据此声称私榜必然领先，也不能写成已经达到 90%。

## 2 数据与评价口径

训练仅使用课程许可的 CIFAR-10 数据，共 50,000 张 32×32 RGB 图片，类别编号沿用比赛的 0–9 映射。前期模型选择使用团队固定划分：45,000 张训练、5,000 张验证，随机种子为 2026。评测集为 2,000 张无标签图片，仅用于生成提交预测。

本地对比使用相同验证 ID，并区分单视图与镜像推理。镜像推理是对同一个模型的原图 logits 和水平翻转图 logits 取均值，再取最大类别；不是两个模型的集成，也不是先取两份类别再投票。Shake-Shake 的评估接口默认包含镜像，单视图测量必须调用 `classify`，避免无意中重复翻转或混淆口径。

全量训练时将原训练和验证部分合并为 50k，因此 A 没有可报告的独立验证准确率。45k 版的 97.54% 不能移作 A 的验证成绩。训练日志中的准确率又受到随机增强、Cutout 和训练态 Shake-Shake 的影响，不能直接与干净验证图的准确率比较。

## 3 优化路径与取舍

### 3.1 先完成对照，再改善容量与训练配方

最初我运行仓库 Wide 配方，目的是建立与组员可比较的起点。该模型约 4.33M 参数，独立 FP32 单视图验证为 95.78%，镜像为 95.84%。随后尝试紧凑结构，以较低训练成本筛选方案；其中较大紧凑模型公榜只有 84.4%，说明训练速度提升并不等于泛化提升。

接着转向约 4.55M 参数的 PreAct SE 结构，配合 CutMix、EMA 和镜像推理，本地达到 96.76%。全量训练并使用预先在验证集上选择的多视图推理后，公榜达到 87.1%。在此基础上加入短程 SAM，本地镜像达到 96.90%，对应全量版公榜为 87.7%。这条路线有效，但仍不足以达到目标。

### 3.2 小幅改进没有持续兑现为更高成绩

我继续尝试了瓶颈残差网络与 RICAP、RegMixup 微调、AugMix 一致性训练，以及权重平均。结果如下。表中“未提交”表示没有确认的公榜成绩，不代表成绩为零。

| 实验 | 本地验证结果 | 公榜结果 | 后续决定 |
|---|---|---|---|
| Compact Large | FP32 95.54% | 84.4% | 不作为主线 |
| PreAct SE 基础版 | FP32 96.76% | 对应全量多视图版 87.1% | 作为 SAM 的起点 |
| PreAct SE 加 SAM | 镜像 96.90% | 对应全量版 87.7% | 保留为后续比较基准 |
| Bottleneck 加 RICAP | 镜像 96.50% | 未提交 | 未超过 SAM，结束该方向 |
| RegMixup 短程微调 | 新训练轮次最高 96.82% | 未提交 | 未超过源模型 96.90% |
| SAM 与 RegMixup 权重平均 | 镜像 97.00% | 未确认提交 | 保留，后用于蒸馏教师 |
| AugMix 加一致性损失 | 新训练轮次最高 96.66% | 未提交 | 未超过源模型，不做全量迁移 |

权重平均采用源 SAM 与 RegMixup 最终 EMA 权重各 50%，再仅用 45k 训练数据刷新 BatchNorm 统计。97.00% 比源模型多判对 5 张验证图片，属于小幅改善，而非决定性突破。

得知组员已开展 SGD、SAM、ASAM、RegMixup、ResNeXt、SupCon 和多尺度系列实验后，我停止继续展开本地 ResNeXt，避免重复占用算力。后续主线改为已披露方案中未覆盖的 Shake-Shake 随机分支正则化。这里的区别依据当时组员披露和仓库记录，未将尚未上传的代码视为已经核实。

### 3.3 转向双分支 Shake-Shake

我选择的思路是在参数上限内增加残差分支的训练随机性，而不是只加深或加宽网络。Shake-Shake 将两个残差分支进行随机加权；本项目实现为前向使用随机系数 α，反向使用独立随机系数 β，每张图片、每个残差块独立采样。评估时两个分支固定各占 0.5。该方法基于 Gastaldi 的 [Shake-Shake regularization](https://arxiv.org/abs/1705.07485)。

在固定 45k/5k 划分上，Shake-Shake-26 2×40d 从零训练 600 轮，搭配 AutoAugment 和 Cutout。最佳权重位于第 600 轮，单视图 97.12%，镜像 97.54%，超过此前 97.00% 的权重平均方案。公榜为 88.2%，仍低于队友随后达到的 89.8%。

这一结果支持继续验证该配方，但也说明本地验证改善并不保证同幅度的公榜改善。训练集划分与独立评测集之间可能存在分布差异；本实验不对隐藏评测集的具体来源作判断，也未获取外部评测标签。

### 3.4 最后并行检验全量重训与在线蒸馏

**A 全量重训**：保留模型、优化器、增强和归一化方式，从随机初始化开始使用全部 50k 图片。为充分利用算力，我先做短时间运行测速，再按 `min(1000, floor(27000 / T))` 确定总轮数，其中 T 为实测每轮秒数。测速 T 约 23.61 秒，因此固定为 1000 轮，余弦学习率从开始就按 1000 轮设置，训练中未临时延长。最终固定导出第 1000 轮，公榜达到 89.9%。

**B 在线蒸馏**：保留 45k/5k 划分，以自身训练的两个教师提供软标签，学生仍从随机初始化开始。该路线尝试让不同模型的预测信息帮助学生，但并未成为最佳提交。700 轮后最佳镜像验证为 97.66%，只比原 Shake-Shake 的 97.54% 多判对 6 张验证图片；公榜为 88.4%。

A 相比原始 45k 版的公榜提升为 **1.7 个百分点**，相比 B 为 **1.5 个百分点**。由于 A 同时改变了训练数据量和总轮数，不能把全部增益归因于“多用 5k 数据”或“多训练 400 轮”；当前实验不是分离这两项因素的严格消融。

## 4 当前最佳配方

### 4.1 网络结构

| 项目 | 实际设置 |
|---|---|
| 模型 | Shake-Shake-26 2×40d |
| 参数量 | **4,561,354**，低于 5,000,000 上限 |
| 输入 | 32×32 RGB |
| Stem | 3×3 卷积，3→16 通道，再接 BatchNorm |
| 三个 stage | 每个 4 个残差块，通道数分别为 40、80、160 |
| 每个块 | 两个平行残差分支，每支包含两个 3×3 卷积，配合 ReLU 与 BatchNorm |
| 下采样 | 第二、第三 stage 首块 stride=2 |
| 投影捷径 | 两条空间错位采样路径，1×1 卷积后拼接并做 BatchNorm |
| 输出 | ReLU、全局平均池化、160→10 全连接层 |
| 训练态分支组合 | 前向 α、反向 β 独立采样；每张图、每个块独立 |
| 评估态分支组合 | 两分支固定平均 |

采用已有残差网络正则化方法，并在比赛参数限制、训练时间与数据约束下实现和组合训练配方；不将 Shake-Shake 本身作为原创方法。

### 4.2 训练设置

| 项目 | 最终 A 的设置 |
|---|---|
| 数据与初始化 | 50,000 张许可图片；随机初始化，无外部预训练权重 |
| 随机种子 | 2026 |
| Epochs / Batch size | 1000 / 128 |
| 优化器 | SGD，momentum=0.9，Nesterov=True |
| Weight decay | 1e-4 |
| 学习率 | 峰值 0.2，前 5 轮为 0.04、0.08、0.12、0.16、0.20，之后余弦降至最后一轮 0 |
| 损失 | 标准交叉熵 |
| 混合精度 | BF16 autocast，未使用 GradScaler |
| 内存布局 | channels_last |
| 加载与 CPU | num_workers=2，cpu_threads=4 |
| cuDNN / TF32 | benchmark=True；TF32 关闭 |
| 权重选择 | 固定第 1000 轮 final.pt；不使用 EMA、SWA、SAM 或蒸馏 |

学习率按 epoch 更新。以从 0 开始的 e 表示轮数，前 5 轮为 `0.2 × (e+1)/5`；之后为 `0.1 × [1 + cos(π × (e−5)/994)]`。恢复训练保留原来的 1000 轮日程，而不是重新开始余弦衰减。

### 4.3 数据增强与归一化

实际增强顺序为：

1. `RandomCrop(32, padding=4, padding_mode="constant")`。
2. 随机水平翻转，默认概率 0.5。
3. torchvision 的 CIFAR10 AutoAugment 固定策略，插值为 NEAREST。
4. ToTensor，将像素缩放至 0–1。
5. 按下列统计归一化。
6. Cutout，边长 16，随机中心，越界部分截断；在归一化后的张量上置零。

```text
mean = [0.4915135944308404, 0.48231470971200857, 0.4468138379970015]
std  = [0.24705092701489773, 0.24347971893365983, 0.2615095063426547]
```

**50k 版保留原 45k 训练部分的归一化统计，没有重新计算。** 训练与提交推理使用同一组统计。采用的是现成 AutoAugment 策略，没有在评测集上搜索增强策略。方法背景见 [AutoAugment](https://arxiv.org/abs/1805.09501) 和 [Cutout](https://arxiv.org/abs/1708.04552)。

### 4.4 推理与提交

加载单个 `final.pt`，使用 FP32、eval 模式，对原图与水平翻转图分别前向，将 logits 等权平均后 argmax。评测阶段不使用随机裁剪、AutoAugment 或 Cutout。输出严格匹配 `test.csv` 的 ID，共 2,000 行，只有 `id,label` 两列。

## 5 在线蒸馏对照配方

B 的学生网络与 A 相同，但保留 5k 验证集，45k 从零训练 700 轮。两个教师均来自自身许可数据训练：PreAct SE 系列的 RegMixup 权重平均模型，以及 600 轮 Shake-Shake。两个教师冻结参数、保持 eval，以 FP32 对学生同一批增强后的图片做单视图前向。

在温度 T=2 下，对两位教师的类别概率各取 0.5 权重得到 q；学生温度概率为 p。损失为：

```text
L = 0.5 × CE(student_logits, label) + 0.5 × T² × KL(q || p)
T = 2
```

学生的其余优化器、数据增强和 warmup 设置与 45k 原始配方一致，余弦日程按 700 轮设置。按 FP32 镜像验证准确率选择最佳权重，分数相同时选择镜像交叉熵更低者。第 690 轮为最佳：4883/5000，即 97.66%。提交时只使用学生，教师不参加推理。

此实验说明这次蒸馏带来了有限的本地改善，但没有取代全量训练路线。不能从单次结果推广为“蒸馏普遍无效”，也不能把两个教师的组合准确率当成学生准确率。

## 6 复现与文件交接

以下路径相对于项目根目录。数据、划分和权重走组内私有渠道，公开分支仅放代码、配置和报告。

| 文件或目录 | 用途 |
|---|---|
| `src/shake_shake.py` | 网络及前向、反向随机分支实现 |
| `src/shake_train.py` | 45k 训练与固定 5k FP32 验证 |
| `src/shake_refit.py` | 50k 从零重训与断点恢复 |
| `src/shake_online_kd.py` | 双教师在线蒸馏对照 |
| `src/predict.py` | 提交推理和 CSV 校验 |
| `src/pixel_cache.py`、`src/utils.py` | 数据缓存、学习率及随机状态等辅助功能 |
| `configs/shake_aa_s2026.json` | 原始 600 轮配方 |
| `runs/shake_aa_s2026/` | 45k 配方选择记录、最佳权重与验证结果 |
| `runs/shake_measured1000_full_runpod_s2026/` | A 的配置、环境、逐轮指标与 final.pt |
| `runs/shake_online_kd700_runpod_s2026/` | B 的配置、指标与 best.pt |
| `submissions/shake_measured1000_full_runpod_s2026/` | A 的提交 CSV 与 metadata |

全量重训脚本会核验原 45k 配方、划分和源权重的哈希。该权重用于核验配方来源，**scratch 模式不加载其参数进行初始化**。因此，不能仅复制一个训练文件就视为完整复现：应保留匹配的源运行记录和依赖模块。没有原始源运行材料时，需要先重新建立并记录来源校验，不能直接跳过校验或宣称与原运行完全相同。

在依赖、许可数据和源运行材料齐全后，从项目根目录执行下列命令。新实验使用新的运行目录，避免覆盖已完成结果。

```powershell
# A：新的 50k 从零训练，固定 1000 轮
python -m src.shake_refit --mode scratch --epochs 1000 --run-dir runs/shake_full1000_reproduction --device cuda

# 导出新的复现实验预测
python -m src.predict --checkpoint runs/shake_full1000_reproduction/final.pt --output submissions/shake_full1000_reproduction/submission.csv --device cuda

# B：可选的在线蒸馏对照，需要两个本地教师目录
python -m src.shake_online_kd --epochs 700 --run-dir runs/shake_kd700_reproduction --device cuda
```

A 实际训练软件环境为 PyTorch 2.8.0+cu128、torchvision 0.23.0+cu128、CUDA 12.8、cuDNN 91002、NumPy 2.1.2、Pillow 11.0.0。GPU 为 RTX A5000。固定种子、配置和数据划分支持实验复现，但启用高效 CUDA 算子后不承诺跨硬件逐位一致。

训练保存优化器和随机状态，逐轮落盘断点，另做定期本地备份。两项训练均已结束、权重与日志已下载校验、云实例已释放。两项任务及一次启动失败尝试的当前已报告费用合计约 6.03 美元，低于 10 美元预算；该数字不是单独 A 的费用，账单也可能存在延迟。

云端提交导出曾因缓存环境缺少原始 PNG 路径而失败，训练本身已完成。最终是在具备完整数据目录的本地环境中加载下载的权重重新导出，并核验 CSV 与权重哈希，因此该问题没有通过重新训练解决，也没有改变模型参数。

## 7 小组报告与分支整理要点

适合写入报告的主要贡献是：在统一划分下完成 Wide 与后续结构对照；记录改进与无效实验；根据组内分工转向不同的残差分支正则化路线；将配方推进到全量从零长日程训练；实现独立的在线蒸馏对照；保留可追溯的配置、断点和提交记录。

建议将最终 Shake-Shake 主线与蒸馏对照分别组织为清晰的代码变更，附上本文和必要配置，避免一次性混入所有临时实验。源代码依赖应完整保留，尤其是 `models.py` 的注册、数据缓存、学习率工具与预测接口。不要向公开仓库上传比赛图片、权重、预测文件、登录凭据或云端密钥。

报告中的结论可以表述为：**在本次实验和预算内，最终采用 4.56M 参数的 Shake-Shake-26 2×40d，在全部许可训练数据上从零训练 1000 轮，以单模型原图加镜像推理达到 89.9% 公榜准确率。在线蒸馏取得更高的独立本地验证成绩 97.66%，但公榜为 88.4%，因此没有作为最佳提交。**

原始证据包括 `experiments/results.csv`、各运行目录的 `config.json`、`summary.json`、`environment.json`、验证记录和提交 metadata；公榜结果同时保留提交回报与组内确认记录。现有实验未进行多随机种子统计，也未得到私榜结果。
